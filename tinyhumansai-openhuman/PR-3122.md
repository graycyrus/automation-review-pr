## AI Summary

**What it does**: Adds a UI control to edit the local AI (Ollama/LM Studio) endpoint from Settings > AI provider chips. Normalizes bind addresses (0.0.0.0 → localhost, [::] → [::1]) across frontend (`validateOllamaUrl`, `AIPanel.tsx`) and Rust layers (`normalize_ollama_client_url`, `validate_ollama_url`). Distinguishes null from absent for endpoint-clearing via RPC using `Option<Option<String>>` + `deserialize_present_json`. Routes `has_model` and `ensure_ollama_model_available` through config-backed URL instead of hardcoded fallback. Secondary changes: issue comment ingestion in GitHub memory reader, OAuth profile graceful recovery for missing tokens, memory graph radius formula update, test fixture fixes for E2E coverage gate.

**Breaking risk**: Low. Changes are additive; existing endpoints continue to work. The `Option<Option<String>>` patch type is backward-compatible. The OAuth credential recovery behavior change (error → silent drop) is a runtime semantic change.

**Security risk**: Zero. Endpoint URL is user-set via authenticated UI, validated through `validate_ollama_url` (scheme allowlist, no userinfo/query/fragment), and `redact_ollama_base_url` prevents credential leakage in logs.

**Bottom line**: Safe to merge structurally, but Rust Core Coverage is failing and two bundled behavioral changes need documentation.

## UI Impact

- **Visual change**: Settings > AI panel now shows a key/edit icon button next to enabled Ollama/LM Studio chips. Clicking opens the existing connection dialog prefilled with the current endpoint URL. Memory graph summary node radius formula changed (level-0 nodes are now 10px instead of 5px; nodes shrink rather than grow with depth).
- **User flow**: Ollama endpoint is now editable without toggling the provider off and back on.
- **Affected surfaces**: AIPanel (Settings > AI), memory graph visualization.
- **Risk**: Low
- **Recommendation**: Approve as-is once CI green; visual memory graph change is minor.
