#### Findings
- [major] `src/openhuman/artifacts/store.rs` — `finalize_artifact` idempotency guard is `status == Ready && size_bytes == size_bytes`. If called twice on an already-Ready artifact with a different `size_bytes` (shouldn't happen but contract isn't enforced), it re-emits `ArtifactReady` and can flap the UI. Should guard on `status == Ready` unconditionally.
- [minor] `app/src/components/chat/ArtifactCard.tsx` — `extensionFor` derives extension from title dot-split as a fallback. This is defensive and fine, but if a title contains a dot (e.g. "Q1 Report v1.2") the extension becomes "2". Could be tightened to only use a suffix that matches a known extension list. Low risk since `create_artifact` controls the title/extension pairing.
- [minor] CI: `Rust Core Coverage` — `inference_voice_http_round23_raw_coverage_e2e` fails asserting `ids.contains("reasoning-v1")`. Unrelated to artifact code but needs author confirmation it pre-dates this PR (especially since `orchestrator/agent.toml` was changed).
