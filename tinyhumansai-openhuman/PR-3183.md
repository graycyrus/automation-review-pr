#### Findings
- [major] `src/openhuman/memory_sync/workspace/watcher.rs:260` — `file_mtime(path)` calls `std::fs::metadata` synchronously inside async `handle_upsert`. Blocks the tokio executor thread under heavy vault activity. Fix: make `file_mtime` async using `tokio::fs::metadata`.
- [major] `src/openhuman/memory_sync/workspace/watcher.rs:284` — `tokio::fs::read_to_string` has no file size guard. Vault files with embedded base64 content or large data exports get fully loaded into memory before the ingest pipeline can reject them. Fix: check `metadata.len()` first and skip files above a threshold (2 MB reasonable).
