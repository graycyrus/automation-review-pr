## AI Summary

| What it does | — | Introduces a process-wide `FileStateCoordinator` singleton that tracks per-agent read stamps and per-path write stamps so that file write tools (`file_write`, `edit`, `apply_patch`) can detect and reject writes based on stale sibling reads. #### Findings
- [major] `src/openhuman/file_state/types.rs:35,38` — `reads` and `writes` HashMaps are unbounded with no eviction or session-scoped cleanup. In long-running server processes handling many sequential agent sessions, every read and write ever recorded accumulates in memory. Needs a session-boundary cleanup hook or TTL-based eviction pass.
- [minor] `src/openhuman/tools/impl/filesystem/apply_patch.rs` — `tokio::fs::canonicalize` called twice per path: once in lock acquisition loop and once in the stale-read guard loop. Resolved paths from the first loop should be retained and reused.
- [minor] `src/openhuman/agent_orchestration/tools/spawn_parallel_agents.rs` — When stale files are detected, the same `stale_parent_reads` list is applied to every task result equally. Functionally correct (parent reminder semantics) but per-result attribution of which child caused which staleness is lost.

CodeRabbit findings (not repeated here): apply_patch lock ordering deadlock (critical), missing path lock in file_write (major), extra-await race in file_read (major), non-unique bus agent ID (major), Instant equality (major), case-insensitive env parse (minor).
