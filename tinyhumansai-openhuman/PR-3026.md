## AI Summary
| Dimension | Rating | Detail |
|-----------|--------|--------|
| What it does | — | Adds a persistent "Files in this chat" panel (header chip + popover) that lists every agent-generated artifact per thread, with Download / Reveal-in-folder / Delete actions. Wraps `chatRuntimeReducer` with `persistReducer` so `ready` artifact snapshots survive app restarts. Also ships the `generate_presentation` Rust tool (python-pptx backed) and the Tauri `download_artifact_to_downloads` command. |
| Breaking risk | Low | FE-only for the panel; net-new Redux persistence key `chatRuntime` (no prior data to migrate); Rust side adds new tool registration and artifact store helpers. No public API changes. Stacked on #3017 — can't merge until that lands. |
| Security risk | Medium | `download_artifact_to_downloads` Tauri command validates absolute path + file-exists but does NOT constrain `source_path` to the workspace artifacts sandbox — a compromised renderer could use it as a general-purpose file copier. Temp file in `generate_pptx.py` uses a predictable PID-based path (local symlink/clobber risk). |
| Bottom line | Not safe — security + functional issues open | The approval-gate bug (`register_artifact_surface_subscriber` only called when `OPENHUMAN_APPROVAL_GATE=1`) means artifacts never bridge to the web channel in standard config. The sandbox constraint on `source_path` is a security hole. Several other CodeRabbit-flagged issues remain open. |

#### Findings
- [major] `app/src/store/artifactsPersistFilter.ts` / `store/index.ts` — `rehydrateArtifactsFromPersist` casts stored JSON to `ArtifactsByThread` with no version guard or shape validation. Follow-up schema changes (adding `thread_id` to `ArtifactSnapshot`) will silently produce malformed objects on first post-upgrade launch.
- [major] `app/src/services/artifactDownloadService.ts` + `app/src-tauri/src/artifact_commands.rs` — Stale persisted `ArtifactSnapshot.path` values (workspace moved, artifacts cleaned) fail with `DOWNLOAD_FAILED` generic copy. `ErrorKind::NotFound` from the Tauri source-read should map to a distinct `FILE_NOT_FOUND` error code so the panel can show an actionable message.
