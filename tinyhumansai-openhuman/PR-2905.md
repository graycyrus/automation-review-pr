## AI Summary

**What it does**: Introduces a `TokenProvider` abstraction (`Arc<dyn Fn() -> Result<String, String> + Send + Sync>`) so the socket reconnect loop re-fetches the session token from the profile store before each attempt rather than reusing the token captured at spawn time. On an "Invalid token" rejection, the loop checks once for a fresher token, then fast-fails with a "session expired" error state if the token is unchanged or the provider errors — instead of burning all 5 retry attempts.

**Breaking risk**: Zero — `connect()` external API is unchanged; `connect_with_provider` is purely additive.

**Security risk**: Zero — token values are never logged (only lengths), no new auth surfaces introduced.

**Bottom line**: Safe to merge — targeted bug fix with comprehensive test coverage and no API changes.
