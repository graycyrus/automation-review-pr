## AI Summary

- **What it does**: Attaches the signed-in user's mongo ObjectId to the process-global Sentry scope at login/account-switch (`store_session`) and clears it on logout (`clear_session`), so background-loop errors (e.g. periodic Composio sync) carry `user.id` even when the lazy `before_send` identity cache is cold. Adds a boot-restore warmer (`warm_sentry_user_from_active_session`) for sessions resumed without going through `store_session`. Only `user.id` is sent — never email/name/IP.
- **Breaking risk**: Zero. Purely additive observability change; no public APIs, types, or config formats altered.
- **Security risk**: Zero. No PII beyond the user's own opaque ID is added to the Sentry scope; `send_default_pii: false` is preserved; blank IDs are guarded.
- **Bottom line**: Safe to merge — clean implementation of session-boundary Sentry tagging, mirrors the backend pattern.
