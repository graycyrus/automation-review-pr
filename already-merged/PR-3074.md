## AI Summary
- **What it does**: Introduces a dedicated `action_dir` (defaults to `~/OpenHuman/projects`, env `OPENHUMAN_ACTION_DIR`) as the cwd and path-resolution root for all acting tools (shell, file, git, node, npm, curl, workflow, etc.), replacing the previous use of `workspace_dir` for tool execution. Internal workspace state (memory DBs, sessions, tokens, persona files) is blocked from agent tool access via `SecurityPolicy.is_workspace_internal_path()`. The Settings UI gains an informational "Directories" section showing both roots.
- **Breaking risk**: Medium. Behavioral change for existing users: relative paths in tool calls previously resolved against `workspace_dir`, now resolve against `action_dir`. Silent for most users since action_dir defaults to the pre-existing `~/OpenHuman/projects`, but any user who had relative-path workflows anchored to workspace_dir will silently break.
- **Security risk**: Medium. The application-layer blocking is well-designed but incomplete: (1) `artifacts/` and `skills/` are missing from the internal-path blocklist; (2) shell command content (not path parameters) can still reference internal paths via absolute paths since `cwd_jail` OS-level jailing is not wired.
- **Bottom line**: Not safe to merge as-is — two internal-state directories missing from the blocklist and the cwd_jail acceptance criterion from #3052 is unmet.

## UI Impact
- **Visual change**: New "Directories" section in Settings → Agent OS access, showing action sandbox (read/write) and internal state (agent-blocked) with hardcoded path strings.
- **User flow**: Unchanged — informational display only, no interactive controls.
- **Affected surfaces**: AgentAccessPanel.tsx only.
- **Risk**: Low (display only; hardcoded paths already flagged by CodeRabbit as a follow-up item).
- **Recommendation**: Approve as-is for the UI section; the hardcoded paths are acknowledged and deferred to a follow-up RPC endpoint.
