## AI Summary

**What it does**: Replaces 2N per-id SQLite queries in `fetch_leaves` (one `get_chunk` + one `get_score` per id) with two upfront batched reads (`get_chunks_batch` + `get_scores_batch`), each issuing a single `SELECT … WHERE id IN (…)` per `MAX_FETCH_BATCH=500` window. At the existing `MAX_BATCH=20` call-site cap, this drops 40 round-trips to 2. Semantics are fully preserved — ordering is maintained by walking the input slice and doing HashMap lookups; missing ids are silently absent; score 0.0 fallback is unchanged.

**Breaking risk**: Zero — no exported function signatures changed; `fetch_leaves` API is identical; only two new pub functions added.

**Security risk**: Zero — dynamic SQL is built from integer ranges and hardcoded column names only; user-supplied values are bound via params. No OWASP concerns.

**Bottom line**: Safe to merge.
