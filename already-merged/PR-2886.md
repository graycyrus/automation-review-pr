## AI Summary
- **What it does**: Fixes a lock contention bug introduced in #2756 where the first `search_cross_thread_messages` call after process start held both `CONVERSATION_STORE_LOCK` and `CONVERSATION_INDEX_CACHE.lock()` for the entire JSONL rebuild duration (~multi-second stall for large workspaces). The fix implements a split-lock strategy: warm-cache path acquires only the cache lock, cold-path briefly acquires store lock to snapshot thread list then releases it before reading JSONL files.
- **Breaking risk**: Zero — internal lock implementation detail, no public API changes.
- **Security risk**: Zero — no new inputs, no auth changes, no serialization of external data.
- **Bottom line**: Safe to merge — purely internal concurrency fix with correct lock ordering and good test coverage.
