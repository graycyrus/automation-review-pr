## AI Summary
- **What it does**: Refactors `cron_run` RPC handler to return immediately with `{status: "queued"}` instead of blocking for the full job duration. Spawns execution in a background `tokio::task`, guards against duplicate concurrent runs with a `Lazy<Mutex<HashSet<String>>>`, and updates the frontend to poll `openhumanCronRuns` every 2s (up to 120s) until a new run record appears.
- **Breaking risk**: Low. The RPC response shape changes (`duration_ms`/`output` become optional, `status` gains a `"queued"` variant), but the TypeScript types are updated in the same PR. Legacy `"ok"/"error"` paths still work.
- **Security risk**: Zero. No new surfaces; the config clone into the spawned task is standard Rust async practice.
- **Bottom line**: Not safe to merge yet — orphaned placeholder rows pollute run history, and a bundled test expectation flip in memoryGraphLayout hides a potential regression.

## UI Impact
- **Visual change**: "Run Now" button shows "Running..." spinner while polling, clears on job completion or 120s timeout. Ghost "queued" rows still appear in run history (see findings).
- **User flow**: Modified — async dispatch + polling loop added. Spinner lifecycle now tied to poll exit condition, which is correct after Review 2 fixes.
- **Affected surfaces**: Routines page, "Run Now" button interaction, run history panel.
- **Risk**: Low (UX logic correct now; history pollution is data-layer issue)
- **Recommendation**: Needs orphaned-row fix before QA sign-off.
