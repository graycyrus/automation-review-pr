## AI Summary

**What it does**: Implements a full skills execution layer — scheduled-skills dashboard at `/skills` → Runners tab, `/skills/run` focused runner with `[[inputs]]` form, `/skills/new` authoring page with `skill.toml` generation, a `[github]` preflight gate (Composio connection, git install, git identity), GitHub I/O via Composio replacing `gh` CLI in bundled skills, and a codegraph (tree-sitter + SQLite FTS5 + dense embeddings) indexer/searcher as agent tools. This is the successor to the QuickJS runtime removal — skills can now actually run end-to-end.

**Breaking risk**: Low. New RPC endpoints added (`skills_run`, `skills_describe`, `skills_recent_runs`, `skills_read_run_log`). Existing `skills_*` controllers are unchanged. `ops.rs` re-exports `SkillCreateInputDef` (additive). New routes `/skills/new` and `/skills/run` added to `AppRoutes.tsx`. `DevWorkflowPanel` migrates config persistence from localStorage to cron backend — existing localStorage entries are silently ignored.

**Security risk**: Low. CEF sandbox escape guarded behind `#[cfg(debug_assertions)]` (correct). All SQLite queries use parameterized `params![]` (no SQL injection). `skill_id` validation is exact-match against registry (no path traversal). Log paths use `sanitize()`. `skills_read_run_log` resolves by UUID prefix scan within `.runs/` (no caller-supplied path).

**Bottom line**: Safe to merge — one functional regression (form state not restored from existing cron job) should be fixed before shipping.
