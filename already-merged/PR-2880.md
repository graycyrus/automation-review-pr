## AI Summary

**What it does**: Adds a full skills dashboard (Runners sub-tab at `/skills`), new `/skills/new` and `/skills/run` pages, a codegraph retrieval engine (BM25+dense RRF fusion over git-tracked files), a `[github]` preflight gate for skill.toml opt-in, the `run_skill` agent tool for skill chaining, and migrates all three bundled skills to use Composio for GitHub I/O instead of `gh` CLI. Also exposes `cron_add` as an RPC, migrates DevWorkflowPanel from localStorage to the cron backend, and adds `skills_run` / `skills_recent_runs` / `skills_read_run_log` / `skills_describe` RPC endpoints. This is a rebase+format-fix of #2875.

**Breaking risk**: Low. New RPC endpoints are additive; existing endpoints unchanged. `ops.rs` re-exports extended with backward-compat serde defaults. DevWorkflowPanel migration from localStorage to cron is data-migration-free (the cron list RPC is the new source of truth).

**Security risk**: Low. No hardcoded secrets, no injection surfaces introduced. The `OPENHUMAN_CEF_NO_SANDBOX` override (`app/src-tauri/src/lib.rs:2026`) is the one notable item — it's a deliberate dev tool but lacks a `#[cfg(debug_assertions)]` build-mode guard, so it ships in production release builds. This means any process that can set env vars before app launch could disable the CEF renderer sandbox on Linux. Low severity since it requires user-level code execution to exploit, but should be guarded. `skillPrompt` in `DevWorkflowPanel.tsx` also interpolates GitHub-sourced strings (repo/branch names) without newline sanitization — minor prompt-injection surface.

**Bottom line**: Safe to merge once CI passes and the two minors are addressed.
